# خطة إصلاحات مكتبة quran_library (الإصدار 4.3.0)

النطاق: المكتبة فقط (لا تغييرات في تطبيق alquranalkareem ولا نقل مجلدات في هذه الدورة). الملف المتغير حاليًا في git (patched_preload_page_view.dart) لا نلمسه.

## الإصلاح 1 — حذف ملف ZIP بعد نجاح الاستخراج
الملف: lib/src/quran/core/services/zip_download_service.dart
- بعد نجاح الاستخراج (extractionSucceeded = true ثم الخروج من الحلقة) وقبل إرجاع onProgress(100.0): حذف ملف zipFile داخل try/catch صامت مع log عند الفشل.
- الحذف الحالي موجود فقط في مسارات الفشل — هذا يكمل السلوك.
- المكسب: ~7-9MB لكل مستخدم فعّل القراءات/التصريف/الإعراب/المعنى/تجويد الآية.

## الإصلاح 2 — تحصين isKindDownloaded بفحص الملفات الفعلية
الملفات:
- lib/src/quran/data/repositories/word_info_repository.dart (isKindDownloaded عند السطر ~85)
- lib/src/quran/core/services/sura_json_files_service.dart (فحص tajweed_aya عند السطر ~32)
- على المنصات غير الويب: إذا كان علم GetStorage للنوع موجودًا لكن مجلد الاستخراج (dirName مثل word_qeraat) غير موجود أو فارغ: إزالة النوع من الأعلام المحفوظة وإرجاع false — فيتيح إعادة التنزيل عند الطلب بدل تعطّل الميزة بصمت.
- يبقى سلوك الويب كما هو (أعلام فقط).

## الإصلاح 3 — ترقيم إصدار كاش الخطوط
الملف: lib/src/quran/core/services/quran_fonts_service.dart
- إضافة ثابت مثل static const int _cacheVersion = 2 (الرقم 2 لأن 4.2.x حدّثت الخطوط والمستخدمون القدامى يملكون كاشًا قديمًا).
- في _ensureCacheDir: قراءة ملف version.txt داخل quran_fonts_cache (إن غاب أو اختلف الرقم → حذف محتويات المجلد وإعادة إنشائه ثم كتابة الرقم الجديد).
- النتيجة: تحديثات الخطوط القادمة (مثل commits "Update Tajweed fonts") ستصل للمستخدمين القدامى تلقائيًا بإعادة فك خلفية واحدة (159MB مرة واحدة بعد التحديث).
- clearCache() الحالية تبقى تعمل كما هي (حذف المجلد يكتي، ويُكتب version.txt عند الإعادة).

## الاختبارات والتحقق
- إضافة اختبارات وحدة في test/ للمكتبة (إن لم يوجد test/ ننشئه):
  1. منطق إبطال كاش الخطوط: version.txt غائب/مختلف/مطابق (بعزل منطق القرار في دالة قابلة للاختبار).
  2. isKindDownloaded: علم موجود + مجلد مفقود → false ومسح العلم (بمجلدات مؤقتة في Directory.systemTemp).
  3. خدمة ZIP: نجاح الاستخراج → الملف المضغوط محذوف (بعنوان URL محلي/محاكاة).
- التحقق: dart format على الملفات المتغيرة + flutter analyze + flutter test داخل مجلد المكتبة.

## خارج نطاق هذه الدورة (توصيات موثقة من التحليل، بلا تنفيذ)
1. سبب 1.25GB: 146MB APK شامل (بلا ABI splits) + 1.11GB بيانات معظمها تنزيلات مستخدم (صوتيات 2.9-3.5GB لكل قارئ كامل، نماذج AI حتى ~450MB، كتب، تفسيرات حتى 120MB) + 159MB خطوط تُفك تلقائيًا. الحل العملي شاشة إدارة تخزين في التطبيق + تمكين splits/AAB.
2. نقل مجلدات المكتبة من Documents إلى getApplicationSupportDirectory مع ترحيل تلقائي: فائدته إخفاء الملفات المولدة عن مجلد مستندات المستخدم على iOS/macOS/Windows واستثناء 159MB الخطوط من نسخة iOS الاحتياطية — دورة منفصلة قادمة.
3. إعادة تسمية ملفات التفسيرات المنزلة (تحمل .json.gz ومحتواها JSON مفكوك) — تحسين تجميلي.
